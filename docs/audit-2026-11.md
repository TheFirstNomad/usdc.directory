# Security and reliability audit, November 2026

Scope: edge functions, shared payment code, paid agent API and MCP, RLS migrations, key frontend pages.

## Fixed in this pass

| ID | Issue | Fix |
|----|-------|-----|
| C1 | BNB USDC (18 decimals) compared against 6-decimal prices, so dust paid for a 25 USDC boost | All amounts are normalised to 6-decimal USDC in `_shared/payment-math.ts`; one verifier in `_shared/payment-verify.ts` is used everywhere |
| C2 | One transfer could fund several paid actions (each feature deduped on its own) | `used_payments` with a unique (chain, tx hash); every paid function claims the transaction before granting anything |
| C3 | Replay race in the paid API / MCP batch | Claim is atomic; MCP batches are capped at 10 and run sequentially; insert errors are checked |
| H1 | Sui and Near payments advertised but unverifiable (payer lost funds) | Sui and Near verifiers added to the shared module. Near needs the paying account in `X-Payment-Signer`, and only transfers from the real Near USDC contract count |
| H2 | Legacy EIP-3009 path made the server pay gas on any chain, including Ethereum | Restricted to Base, Arbitrum, Optimism, Polygon, Avalanche; strict field validation, no uncaught throws |
| H3 | `circle-proxy` path lock bypassable with `..`, caller could override Authorization | Path parsed and normalised, `..`/encoded dots rejected, GET/POST only, caller headers never forwarded |
| H4 | Agent `website`/`logo_url` unvalidated, rendered as href (script URL = stored XSS) | Server-side `safeHttpUrl` on every write path; frontend never renders a link or image URL that is not http(s); agent ownership is bound to the paying wallet |
| H5 | Boosting an unknown id charged the caller; re-boosting reset the timer | Target checked before payment; boosts extend the window; on-chain payments are released for retry if delivery fails |
| M1 | Unbounded MCP batch | Max 10 messages |
| M2 | No limit on failed payment attempts | Per-caller limit before any chain RPC call |
| M3 | Boost slot cap checked before payment verification | Checked before and again after the claim; payment released if the last slot was taken |
| M4 | `VITE_SUPABASE_PROJECT_ID` used by admin pages; `/admin/health` unguarded | Functions URL comes from the validated backend URL; health page behind `AdminGuard` |
| M5 | SVG logo uploads unscreened | Scripts, handlers, external refs and embedded documents rejected |
| M6 | `og-agent` unescaped emoji, truncated entities | Escaped; truncate before escaping |
| Low | Clearbit logo lookups leaked viewed domains | Removed; local fallback logo |

## Operator checklist (needed after publishing)

1. Publish so the new migration (`20261124000001_used_payments.sql`) is applied. Paid actions fail closed (503) until the `used_payments` table exists.
2. Redeploy the edge functions. Publishing the frontend alone does not update them.
3. Rotate `VITE_ARC_KIT_KEY` in the Circle Console (it was exposed earlier and is still read by client code).

## Not changed (follow-ups)

- Admin session tokens are stateless and valid for 8 hours; there is no revoke list.
- `og-agent` still loads its wasm from esm.sh at runtime.
- `VITE_ARC_KIT_KEY` is still bundled into client code by `arcAppKit.ts`.
- Arc is on-chain tx-hash fallback only (not Gateway gasless).

## Tests

- `vitest`: payment math (BNB regression), proxy path allow-list, URL and text safety, SVG screening, frontend URL helper.
- Deno (`supabase/functions/agents-api/core.test.ts`): updated and extended (script URLs, legacy EIP-3009 on Ethereum, malformed authorization). Deno is not installed in the Arc Studio sandbox, so these were not executed here. Run `deno test` locally or in CI.
